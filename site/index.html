Run AI work from a plan you can check

Agent Playbook OS turns a written playbook into a run that follows the steps in order, stops for a person where you ask, carries on from where it stopped, and leaves a record that shows if anyone changed it.

How it works

Write it, review it, run it, check it

A playbook is a YAML file that lists the steps, their order and who has to approve what. The same file gives the same plan every time, so you can repeat a run, compare two runs and audit one later.

01 · WRITE

Write the playbook

Steps, inputs, approvals and limits in one versioned file.

playbook validate
02 · REVIEW

Review the plan

It compiles into a fixed plan with each skill pinned, so what you review is what runs.

playbook compile
03 · RUN

Run and approve

Steps run in order. The run pauses where a person has to sign off and carries on when they do.

playbook run · resume
04 · CHECK

Check the record

Every run keeps its history, and one command tells you whether any of it was changed.

playbook verify

Get started

Try it from a clone

There is no release yet, so you install from the repository. You need Python 3.11 or newer and uv. These commands were run on a fresh clone on 11 Nov 2026.

STEP 1

Clone and install

uv creates a local environment with the playbook command in it.

$ git clone https://github.com/CometWeb-io/agent-playbook-os $ cd agent-playbook-os $ uv sync
STEP 2

Run the demo

It runs two steps, then stops and waits for your approval.

$ uv run playbook run \ playbooks/examples/kernel-demo.yaml \ --input name=Ada --run-root .playbook-runs "status": "WAITING_APPROVAL"
STEP 3

Approve and check

Use the run folder the first command printed.

$ uv run playbook resume .playbook-runs/<RUN> \ --approve approval --approval-actor you@example.com "result": "approved for Ada" $ uv run playbook verify .playbook-runs/<RUN> "ok": true

Preview status

What it does not do yet

This is a public source preview. The limits below come from the repository's own release-readiness notes.

01

A preview, not a release

No version tag and no PyPI package. Install from a clone, and expect files and commands to change.

02

Not yet tested with a live agent

The examples run on a built-in reference runtime. Adapters for real hosts are sketched but not tested end to end.

Claude Code Codex Cursor
03

An intact record is not a right answer

Verify shows the record was not changed. It cannot tell you whether a model's answer or a real-world action was correct.

04

One machine, no sign-in

Runs are stored in files or SQLite. Shared production storage and real sign-in for approvers are not covered yet.
